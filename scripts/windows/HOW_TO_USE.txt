========================================
AUDIO TRANSCRIPTION - HOW TO USE
========================================

FIRST-TIME SETUP (Windows machine without WSL):
1. Install Docker Desktop from
   https://docs.docker.com/desktop/install/windows-install/ and start it.
2. git clone https://github.com/<your-fork>/stt-faster C:\projects\stt-faster
3. cd C:\projects\stt-faster
4. setup.bat        (builds the stt-faster:latest image; 5-15 min first run)
5. Done. The bats in scripts\windows\ work as-is.

WSL users can skip steps 1 and 4 — the bats detect WSL automatically.

The bats auto-detect WSL: if WSL2 is installed AND the repo is present at
/home/kristjans/projects/stt-faster inside WSL, they run there (preserving
the current dev-machine workflow). Otherwise they fall back to a Docker
container built from the production Dockerfile (CPU-only). The runtime
banner at the top of each run prints the choice:
  [stt-faster] runtime: wsl     (or 'docker')

========================================

TWO WAYS TO USE THE BATS:

(a) Copy-into-folder (legacy, no env var needed):
    Copy the bat for your audio source into the folder containing the audio
    files (e.g. C:\Users\PC\Downloads\transcribe\), then double-click it.
    The bat treats its own folder as the audio dir.

(b) Env var + run-in-place:
    set STT_AUDIO_DIR=C:\Users\PC\Downloads\transcribe
    Then double-click any bat directly under scripts\windows\. The bats
    honor STT_AUDIO_DIR over their own folder when both are present.

Transcripts land in:
    <audio_folder>\processed\          (single-variant runs)
    <audio_folder>\<timestamp>\        (multi-variant runs)
Failed files land in:
    <audio_folder>\failed\

========================================

BATCH FILES:

ESTONIAN:
  transcribe_estonian_Desk.bat       - Desk-mic / close-talk, variant 44
  transcribe_estonian_Teams.bat      - Teams / video-call, variant 61
  transcribe_estonian_Online.bat     - Online / mixed-source, variant 52
  transcribe_estonian_32bit_cpu.bat  - CPU-only machines (et-32 preset),
                                       variant 7

ENGLISH (uses 'turbo' preset):
  transcribe_english_Desk.bat        - Desk-mic / close-talk, variant 44
  transcribe_english_Teams.bat       - Teams / video-call, variant 61
  transcribe_english_Online.bat      - Online / mixed-source, variant 52

UTILITIES:
  compare_variants.bat               - Runs every builtin variant against a
                                       single audio file and generates the
                                       HTML comparison report.
  report_only.bat                    - Regenerates the variant HTML report
                                       from existing outputs (no transcription).
  check_status.bat                   - Shows recent transcription run history.

To use a different variant, edit the `set "VARIANTS=..."` line at the top of
the batch file. Space-separated values run multiple variants in one go,
e.g. `set "VARIANTS=1 36 44"`.

========================================

SUPPORTED FORMATS:
  .wav  .mp3  .m4a  .flac  .ogg  .aac

========================================

OUTPUT:
Each audio file generates a .txt transcript with range timestamps and
speaker labels by default:

  [00:00:00.40 --> 00:00:03.05] SPEAKER_00: Tere, kuidas läheb?
  [00:00:03.10 --> 00:00:05.70] SPEAKER_01: Aitäh, hästi.

That is the default for the 7 production 1:1-meeting bats
(transcribe_estonian_*.bat, transcribe_english_*.bat).

compare_variants.bat is the one exception: it still emits .json + .txt
(--output-format both) and runs with --no-diarize, because the variant-
comparison report consumes JSON and doesn't need speaker labels per variant.

Diarization requires a HuggingFace token; see
  docs\diarization_setup.md
for first-time setup. To skip speaker labels in a custom run, pass
--no-diarize to transcribe_manager.py process (timestamps stay).

Single-variant runs land under:   <audio_folder>\processed\
Multi-variant runs land under:    <audio_folder>\YYYY-MM-DDTHH-MM-SS\
                                  (flat files named variant_NNN_<name>_<audio>.json
                                  plus a run_meta.json describing the run)
Failed inputs land under:         <audio_folder>\failed\

========================================

NOTES:
- The Docker fallback is CPU-only by design. For GPU acceleration use WSL
  (the bats prefer it automatically when available).
- Run history (`runs.jsonl`) is per-runtime: WSL writes to
  ~/.local/share/stt-faster/runs.jsonl inside WSL; Docker mounts
  %USERPROFILE%\.local\share\stt-faster\ into the container and writes
  there. Both runtimes on the same box keep separate histories.
- The hardcoded WSL repo path that controls auto-detect lives in
  scripts\windows\_runtime.bat (STT_WSL_REPO=...). Edit it if you move the
  WSL repo.
- First run downloads the model (~1.5-3 GB). Models cache at
  ~/.cache/hf inside WSL or %USERPROFILE%\.cache\hf on Windows (mounted
  into the Docker container).

========================================

TROUBLESHOOTING:
1. Banner says `runtime: docker` but you expected `wsl`:
   - Check `where wsl` returns a path and that
     `wsl -e test -x /home/kristjans/projects/stt-faster/.venv/bin/python`
     exits 0. Both probes must pass for the WSL branch to fire.
2. Banner says `runtime: wsl` but you wanted to test the Docker path:
   - Temporarily rename the WSL .venv, or override STT_WSL_REPO in
     scripts\windows\_runtime.bat to a path that doesn't exist.
3. "ERROR: no runtime available":
   - Neither WSL nor Docker is usable. Install Docker Desktop, start it,
     and re-run setup.bat from the repo root to build the image.
4. Diagnostic status (any runtime):
   - Run check_status.bat.
